## Границы проекта

- Не позиционировать результат как юридическую консультацию.
- Не утверждать факт нарушения; возвращать только риск-сигналы, неопределенность и безопасные следующие шаги.
- Не хранить токены WB/Ozon, пользовательские документы, API-ключи, cookies и приватные payload в репозитории.
- Внешние продукты использовать только как функциональный ориентир: не копировать бренд, тексты, дизайн, изображения, CSS/HTML или уникальные формулировки сторонних сайтов.
- Реальные секреты хранить только в локальном `.env` или deployment secret store.

## Разработка

```bash
make setup
make test
make compile
```

Для production-like контейнера:

```bash
cp .env.example .env
docker compose up -d --build
```

## Правила изменений

- Risk engine должен оставаться explainable: каждый балл должен быть связан с понятным trigger.
- Если данных недостаточно, добавлять пункт в `uncertainty`, а не угадывать.
- Новые правила покрывать тестами.
- Интеграции с marketplace API, OCR, image similarity или trademark databases добавлять только с явными ограничениями по ToS, rate limits, секретам и правовому статусу результата.
